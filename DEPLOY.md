## Redeploy after an edit

```bash
cd site-v4
vercel deploy --prod --yes
```

The directory is already linked (`.vercel/project.json`). If a shell is not a TTY, prefix with
`NO_UPDATE_NOTIFIER=1` or the CLI's update worker crashes with `EPIPE` on Windows.

## Deployment Protection

The **team default** is `all_except_custom_domains` — i.e. every `*.vercel.app` URL is behind
Vercel SSO until a custom domain is attached. This project overrides it to **`preview`**, so
production is public and previews stay private.

Check / change it:

```bash
vercel api "/v9/projects/prj_th5hWVuZTeIhNtqVB46Wg7GE3RVw?teamId=team_FFzZ7j2gPKEvVuXnCHzj7eW1" \
  -X PATCH --input <file with {"ssoProtection":{"deploymentType":"preview"}}>
```

Note `--input` needs a **native Windows path** (`C:/...`), not an MSYS path (`/c/...`) — otherwise
the CLI silently fails to read the file.

## Known gaps

- `hello@higherheights.studio` is the contact address, but **higherheights.studio does not resolve
  in DNS**. Either register it or change the address on the page.
- `og:image` / `canonical` point at the `*.vercel.app` host. Update both (and `robots.txt` +
  `sitemap.xml`) once a real domain is attached — they are generated by `postdeploy.py`.
- Deployment IDs change on each deploy; use the stable project alias above, not
  `higher-heights-<hash>-....vercel.app`.
